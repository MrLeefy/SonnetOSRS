# Classic interface implementation — v0.3

## Visual direction

The user's approved landscape reference guided the arrangement: roughly 72% left-side world/chat and 28% right-side minimap/inventory, integrated earthy stone/bronze trim, parchment message area, brown inventory, classic circular orbs and red active tabs. Portrait reflows the same components instead of switching to a green mobile-app theme.

The shipped interface is rendered from live game state. There is no mockup texture over the game, no fabricated inventory content and no unrelated map image. The 28 slots, equipment, prayers and magic actions invoke the original functions. The minimap uses the existing rotating terrain raster with real object/actor markers and the original movement command.

## Modules

- `classic.js`: cached procedural stone/paper/brown textures, original pixel glyphs, beveled frames/rings and pure layout calculations.
- `client.js`: composite presentation, per-slot coordinate conversion, real chat, live minimap/orbs, accessible native hit targets and parchment/stone dialogs.
- `classic_presenter.js`: a small explicit adapter after `polish.js`; removes duplicate legacy chat/menu rendering, produces original logical panels and keeps WebGL resolution aligned with the composed viewport.
- `tools/build.py`: includes the three presentation pieces in a deterministic 22-module standalone build.

The existing game, engine extension, expedition, profiles, controls, AI, items and world modules are verified byte-for-byte against v0.2 by a regression test. Their mechanics and save schema are unchanged.

## Interaction details

Every resizable inventory cell maps to its original `invSlotRect`. Other panels are uniformly scaled, not stretched. Resizes cancel pending gestures before changing hit geometry. Safe-area padding is read from CSS env insets and applied to frames and controls together.

Mouse and touch menus use the same real action entries. A long press never consumes an item until an explicit menu choice, and touch release suppression remains owned by the tested original gesture state machine. Native text entry avoids needing a hardware keyboard on phones. Menu dialogs pause the existing offline simulation.

The scrollable parchment chat uses actual messages and supports long-word wrapping. Private/clan/trade are visibly offline. Report Abuse explains there is no online report service and exports a local text report only.

## Verification

Locally passed: 65 runtime checks, 30 existing browser checks and 19 dedicated classic-interface checks, for 114 total. Desktop and mobile snapshots are generated by the actual WebGL renderer in Chromium, not image generation. New coverage includes ten screen sizes, notch padding, minimap movement, compass reset, actual prayer/spell/equipment actions, native context menus, chat filters/scrolling, collapsed-chat hit targets, phone rotation during an item press and report-file export.

GitHub Actions runs the same suites; its status is authoritative for hosted CI. Configuring or documenting a workflow does not by itself mean a particular hosted run passed.

## Deliberate limits

This release targets the reference composition and classic visual language with original artwork; it is not a pixel-identical OSRS asset replacement. It does not implement a Rust server, network accounts, multiplayer, new PvP zoning or cloud saves. Mobile tests use Chromium touch emulation, not physical handsets. Full screen-reader gameplay, Safari/Firefox verification and broader device performance measurements remain future work.
